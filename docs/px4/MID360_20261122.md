# Mid-360 接入与测试（2026-11-22）

## 接入方式

新增 `--lidar-model mid360`。模型使用 Livox 官方仿真项目的 `scan_mode/mid360.csv` 扫描方向序列，在当前 msim 分时求交插件中逐批采样；不使用普通均匀线束网格代替 Mid-360，也不采用一次求交整帧后填入不同采样时间的方式。

| 项目 | 当前配置 |
| --- | --- |
| 名义视场 | 水平 360°，垂直 −7°～52° |
| 扫描方向 | 官方 CSV 非重复扫描序列；连续推进跨帧索引 |
| 发射点率 | 200,000 点/s；10 Hz 分帧，每帧最多 20,000 个返回 |
| 量程 | 0.1～40 m；40 m 对应规格中的低反射率测距参考，不模拟材质相关探测概率 |
| 测距误差 | 径向零均值高斯标准差 0.02 m，距离量化 0.001 m |
| 分时求交 | 2 ms 物理步长下每批约 400 次求交，帧内时间覆盖约 0～98 ms |
| 通道标识 | 4 组交错通道，按官方仿真格式分组；不是 4 条固定垂直扫描线 |
| 安装及 IMU | 雷达在机体上方 0.15 m，轴向一致；继续使用现有独立 MEMS ROS IMU，不模拟实物内置 ICM40609 的标定参数 |
| 原始点云 | `/velodyne_points` 保留兼容话题名，字段 XYZ、intensity、ring、time；另发布 `/livox/lidar` 原生 Livox 消息 |
| FAST-LIO 入口 | 自动选择 `livox_ros_driver/CustomMsg`、`lidar_type=1`、`scan_line=4` |
| 算法抽稀 | 默认 `point_filter_num=1` 保留全部有效输入；可显式覆盖 |
| 处理缓冲 | 保留现有 0.65 s LiDAR 处理延迟，采样时间与逐点时间不改写 |

角度、点率和名义视场参照 [Livox 官方规格](https://www.livoxtech.com/mid-360/specs)。40 m 是 10% 反射率条件的测距参考，规格也给出 80% 反射率条件下 70 m；当前环境没有按表面材质切换探测距离。噪声和简化几何只是实验模型，不是厂商逐点精度保证。

## 运行

```bash
cd /home/wzb/msim
./tools/px4-uav-capture.sh --duration-s 60 --fastglio-live --skip-signalsim \
  --flight-pattern route --route-clock sim --lidar-model mid360 \
  --spoof-start-s 25 --spoof-east-rate-mps 0.18
```

去掉两个 `--spoof-*` 参数运行无欺骗组；增加 `--headless` 后仅后台采集并导出图。选型器自动选择 Livox 入口及抽稀参数，不需要额外指定 `--fastglio-frontend`；若显式指定，应使用 `livox`。其他型号仍默认 Velodyne 入口和每两点取一。`--point-filter-num` 可覆盖默认值。

## 时间与消息验证

原始 PC2 与 Livox 消息来自同一次求交结果。`CustomMsg.header.stamp` 为帧开始时间，`timebase` 为相同的纳秒时间；每点 `offset_time` 单位为纳秒，XYZ 与 PC2 完全一致。点坐标属于其采集时刻雷达坐标系，供 FAST-LIO 做运动补偿。

扫描方向序列有 800,000 个样本。文件第一列虽然名为 `Time/s`，实际连续值为 1～800000；当前按顺序索引解释，以配置点率调度。200,000 点/s 下文件约 4 s 回放完后循环。它能提供窗口内的非重复扫描模式，但不代表无限长不重复，也不宣称恢复了真实硬件每束微秒级发射时刻。每批物理求交的时间才是输出采样时间。官方方向序列实际垂直范围约 −7.2123°～52.164°，保留原始方向，不强行裁剪到名义边界。

原始文件固定于 `adapters/gazebo_classic/data/livox/`，保留 MIT 许可证和 `source.json`。上游提交为 `1cce1073633a062b92e30243a4c2920e45551bb5`，CSV SHA-256 为 `aa1fc08b6a4400608dbd6ee832b7ea3a9c3c37197e734f60f58fe5abf762269a`。选择器验证文件摘要；每次采集归档 CSV 及来源信息。[上游项目](https://github.com/Livox-SDK/livox_laser_simulation)

## 已完成检查

- 单元检查覆盖配置选择、错误模式摘要拒绝及从 Mid-360 切回均匀雷达时清除模式元数据。
- 六组 Gazebo 房间检查包括原有 16/32/64 线回归，以及 Mid-360 快照和分时模式；报告：`runs/mid360-20261122/room-check/validation.json`。
- Mid-360 每帧 20,000 个返回，10 Hz，测距残差标准差约 0.02003 m，分时点跨度约 0.098 s。
- 每种 Mid-360 模式核对 16 对同序号 PC2／Livox 消息的 XYZ、时间基准、逐点时间、tag 和通道一致性，全部通过；连续帧方向发生变化。
- 首轮有欺骗飞行 `runs/mid360-20261122/spoofed/` 使用显式四点取一，数据链路、飞行和同步检查通过，但纯 LIO 出现明显漂移。这不是推荐配置，也不能作为定位精度合格的结论。
- 首轮运动扫描在 35 帧、29,237 点上，以独立真值变换后到场景表面距离 RMSE 为 0.01457 m；若整帧都使用开始／结束位姿，则为 0.11187／0.10437 m。报告为该运行目录的 `sensor-upgrade-validation.json`。此项验证点云采样与运动几何，不是导航轨迹误差。

当前 40 m 量程与较窄的向下视场可能导致高空巡航时缺少地面观测，应结合实际点云覆盖分析定位退化，而不能仅凭型号推断其一定比 16 线效果好。

## 最终同配置飞行结果

无欺骗与有欺骗各运行 60 秒，均使用 Mid-360、原生 Livox 前端、`point_filter_num=1`、相同传感器与算法参数、仿真时钟航线。两次飞行为独立闭环实验，不把两条曲线的所有差异归因于欺骗。误差对各自真值计算，仅首个匹配点平移对齐，不拟合旋转或尺度。

以下使用每条曲线的完整有效时间范围，单位均为米；绘图使用共同时间区间，指标可能存在轻微差别。

| 条件 | 方法 | 东向 RMSE | 北向 RMSE | 天向 RMSE | 三维 RMSE |
| --- | --- | ---: | ---: | ---: | ---: |
| 无欺骗 | GPS | 0.686 | 1.089 | 2.560 | 2.865 |
| 无欺骗 | LiDAR/IMU | 0.088 | 0.122 | 3.572 | 3.576 |
| 无欺骗 | LiDAR/IMU/GPS 松组合 | 0.680 | 1.099 | 2.371 | 2.700 |
| 有欺骗 | GPS | 2.566 | 1.072 | 2.480 | 3.726 |
| 有欺骗 | LiDAR/IMU | 0.117 | 0.128 | 3.218 | 3.223 |
| 有欺骗 | LiDAR/IMU/GPS 松组合 | 2.479 | 1.112 | 2.041 | 3.398 |

飞行与同步检查均通过。无欺骗／有欺骗的松组合接受更新次数分别为 609／610；PX4 ULog 与 GPS 注入值匹配率分别约 98.46%／100%，LiDAR 配对比例均为 100%。完整结果位于 `runs/mid360-20261122/{clean-native-pf1,spoofed-native-pf1}/`，汇总在 `test-summary.json`。

纯 LIO 的水平 RMSE 分别为 0.150／0.173 m，但天向仍有 3.572／3.218 m 的明显漂移，因此只判定接入、时序和数据链路通过，不将定位精度视为全面合格。当前 40 m 量程、向下约 7° 的视场与缺少水平结构的走廊可能造成高度可观测性弱；还需要改变飞行高度、安装角或量程的单变量对照才能确认原因。默认使用不抽稀配置以保留空间观测。

最终有欺骗组在 38 帧、31,970 点的独立真值几何检查中，按真实点时间得到场景表面距离 RMSE 0.01673 m；若误用帧开始／结束位姿，则分别为 0.25412／0.21232 m。这验证实际运动采样信息，与上述导航漂移是不同指标。
