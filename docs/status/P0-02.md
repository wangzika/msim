# P0-02：ADR 与运行证据

- 状态：部分完成；P0-01 的镜像验证和工具检查尚未完成，本任务作为前置准备，不视为依赖已通过。
- 目标：记录五项架构决策并提供可审计的运行证据格式。
- 输入：实施方案第 3–5、6.1、13、16 节。
- 依赖：P0-01。
- 验证：运行证据工具的成功、拒绝覆盖及缺失输入测试。
- 风险：尚无 orchestrator，不能声称每次 run 自动产出完整 manifest；Git 元数据不可用时禁止伪造 commit。

## 已完成与验证

五份 ADR 草案已建立。`tools/validation/create_manifest.py` 可生成初步证据，记录场景 SHA-256、显式 seed、Git commit 和 dirty 状态，并拒绝覆盖；无 Git commit 时失败。`ctest --test-dir build --output-on-failure`：本机 2/2 通过，包含证据文件创建、禁止覆盖及错误输入测试。

尚无实际 run/orchestrator，初步证据不包含依赖、镜像、解析后参数、输出校验和等完整内容，不满足每次 run 的 manifest 门禁。尚无可用 Git 仓库，本工作区不能实际产出带 commit 的证据。

P0-01 现已通过本机容器检查；P0-02 本身仍为部分完成，实际运行清单的自动生成及完整字段须随运行器实现后验证。

## 2026-10-29 更新

初步来源记录工具增加可选的解析后场景、产物和依赖锁的 SHA-256、不可变镜像引用及主机信息，缺失文件和非法镜像引用失败，仍拒绝覆盖。契约测试覆盖这些字段、无效输入和既有文件保护。记录仍为 `preliminary`，不能代替自动化完整 run manifest。

本地仓库已初始化但没有提交；Git 提交身份和远端未配置。首次提交前无法生成真实 HEAD 指纹。沙箱中 `.git` 不可写且可能不可见；常规运行时需要能读取真实仓库元数据的环境。

## 2026-10-29：运行证据包装器

新增 `apps/orchestrator/recorded_run.py`：运行兼容的子进程并显式传递场景、seed 和输出目录；保留场景、依赖锁副本、stdout/stderr，记录输入/输出 SHA-256、Git HEAD/dirty、镜像引用（调用者提供）、主机信息、命令和退出码。运行目录已存在时拒绝覆盖；可执行文件不存在时仍记录失败清单。测试 `recorded_run_contract` 覆盖正常执行、记录内容、失败和不覆盖；容器内 3/3 CTest、格式和 lint 及 ROS 占位包检查通过，日志 `logs/P0-02-recorded-run-check.log`。README 提供仅演示证据流的最小样例；使用实际工作区 HEAD 的样例通过，标记 dirty。

此包装器不解析场景、不自动发现或核验镜像及 GPU，也不能保证被调进程实际使用 seed；真实仿真运行器尚未实现或接入，故完整运行清单门禁仍待后续验证。Git 工作区修改仅记录 dirty，不包含其全部内容，不能据此认定完全可复现。
